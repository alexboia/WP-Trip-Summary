# Security Report — abp01-travel-tech-box

- **Date:** 2026-09-24
- **Version reviewed:** 0.3.3, as specified in `abp01-plugin-header.php`
- **Scope:** local plugin source code, AJAX and REST endpoints, public rendering, track uploads and storage, and bundled libraries.
- **Method:** static analysis and isolated local probes, using synthetic data and test doubles for WordPress services where necessary.
- **Changes during the audit:** none to application code or site data.

Severity ratings are estimates for the conditions described, not CVSS scores. Confirming a weakness in code or an isolated probe does not mean exploitation has been demonstrated on the live site. The solution outlines below are proposals and have not been implemented.

## SEC-01 — Disclosure of track data from password-protected posts

### Finding and impact

`FrontendViewerPluginModule::addViewerToContent()` attaches the viewer without checking whether the post requires a password. Data may be added alongside the WordPress password form. Nonces for reading and downloading the track are generated in the same flow.

The AJAX read and download endpoints validate the nonce but do not recheck post visibility or password access. A previously available nonce must not replace current authorization, including after a change in post visibility. The additional REST field and JSON-LD output do not perform their own password checks.

A visitor may therefore obtain geographic information and details that the author expects the post password to protect. Downloading through the dedicated endpoint also depends on the download permission setting. Access to arbitrary private posts through ID enumeration alone was not demonstrated.

### Evidence

- [FrontendViewerPluginModule.php](../lib/pluginModules/FrontendViewerPluginModule.php), lines 176–205: attaching data and generating nonces.
- [GetTrackDataPluginModule.php](../lib/pluginModules/GetTrackDataPluginModule.php), lines 66–95: anonymous access with a nonce, without a visibility check.
- [DownloadTrackDataPluginModule.php](../lib/pluginModules/DownloadTrackDataPluginModule.php), lines 66–98: anonymous access with a nonce and a download setting check.
- [RestApiEnhancementsPluginModule.php](../lib/pluginModules/RestApiEnhancementsPluginModule.php), lines 94–115: supplying the additional field.
- [JsonLdFrontendDataPluginModule.php](../lib/pluginModules/JsonLdFrontendDataPluginModule.php), lines 70–95: emitting coordinates in the page.

The isolated probe invoked the actual content attachment flow using a password form and simulated services. Result: data and the nonce were attached, and the password check was never called.

### Solution outline

1. Introduce a shared access check for a post's trip summary: post existence, visibility to the current user, and satisfaction of password protection requirements.
2. Apply the check before rendering the viewer, generating nonces, emitting JSON-LD, supplying the REST field, and reading or downloading through AJAX.
3. Preserve legitimate editor and preview access through an explicit context that checks the appropriate post permissions.
4. For REST, respect WordPress's mechanism for passwords supplied in the request. On the frontend, use the WordPress password check; `current_user_can('read_post', $postId)` alone does not cover all conditions.
5. Recheck access on every request, including when data is already cached.

**Verification after remediation:** a matrix covering anonymous visitors, users without access, and authorized authors/editors, for public, password-protected, private, and draft posts; test correct and incorrect passwords, and a nonce obtained before access to the post was restricted.

## SEC-02 — Incomplete protection for stored files

### Finding and impact

Uploads are assembled into predictable files named `track-ID.dat`, in the tracks directory, which is located under uploads by default. Generated rules block the `cache`, `gpx`, `geojson`, and `kml` extensions but omit `dat`. A temporary file may be directly accessible during an upload or after an abandoned upload if no other server rules protect it.

Protection for tracks, cache files, and logs relies on `.htaccess`. Servers that do not apply these rules require equivalent restrictions. An `index.php` file does not prevent direct access to a file with a known name.

### Evidence

- [Default.php](../lib/route/track/processor/Default.php), lines 45, 294–302, and 379–388: temporary extension and file names.
- [CreateTracksStorageDirSecurityAssets.php](../lib/installer/service/CreateTracksStorageDirSecurityAssets.php), lines 73–79: protected extensions.
- [CreateLogStorageDirSecurityAssets.php](../lib/installer/service/CreateLogStorageDirSecurityAssets.php), lines 66–69: log protection.
- [Env.php](../lib/Env.php), lines 269–277: default location under uploads.

The existing local rules for the tracks directory have the same omission of the `.dat` extension.

### Solution outline

1. Block HTTP access to the plugin's entire data directory instead of relying on a list of extensions. Legitimate downloads should be served through authorized endpoints.
2. As an immediate measure, include the `.dat` extension and update the rules on existing installations.
3. Prefer storage outside the public document root where the infrastructure allows it; otherwise, document the rules for each supported server.
4. Use separate temporary files for each upload session and remove abandoned files after a defined interval. Hard-to-guess names provide only additional protection.

**Verification after remediation:** direct HTTP requests to synthetic `.dat`, `.gpx`, `.cache`, and `.log` files, including during an unfinished upload; expected response: 403/404. Separately verify authorized downloads through the application.

## SEC-03 — Stored XSS through map attribution

### Finding and impact

`getTileLayerAttribution()` concatenates the configured URL directly into the `href` attribute. Text filtering and URL validation accept certain values containing quotation marks that allow an HTML event attribute to be injected. The data reaches the Leaflet control, which inserts it through `innerHTML`.

Exploitation requires permission to manage plugin settings, available to administrators by default. This is not an attack path for anonymous visitors or authors with default permissions. The trust boundary is particularly relevant in multisite installations and for delegated roles without permission to publish arbitrary JavaScript.

### Evidence

- [abp01-map.js](../media/js/abp01-map.js), lines 330–345: HTML construction.
- [Url.php](../lib/validate/Url.php), lines 86–96: URL validation.
- [abp01-plugin-functions.php](../abp01-plugin-functions.php), lines 436–459: the `ARRAY_A` branch of `abp01_esc_js_object()` preserves values unchanged.
- [leaflet-src.js](../media/js/3rdParty/leaflet/leaflet-src.js), line 5701: inserting attribution through `innerHTML`.

The local probe passed a synthetic value through filtering, validation, and the conversion used for settings. Parsing the resulting HTML confirmed the attribute `onmouseover="window.auditMarker=1"`. No attack was executed in a browser, and no settings were saved to the database.

### Solution outline

1. Build the link with `document.createElement('a')`, assign the URL through the appropriate DOM property or API, and assign the text through `textContent`.
2. If the Leaflet API requires an HTML string, serialize the element constructed this way instead of concatenating values.
3. Restrict URL schemes to those required by the feature, usually HTTP and HTTPS.
4. Treat attribution text as plain text. Validation when saving complements, but does not replace, protection when rendering.

**Verification after remediation:** values containing quotation marks, apostrophes, HTML entities, and disallowed schemes; the resulting DOM must not contain event attributes or additional elements. Verify legitimate attribution values and Unicode characters.

## SEC-04 — Directory traversal in the Leaflet wrapper

### Finding and impact

The public script that wraps Leaflet extensions accepts the `load` parameter. Filtering permits `../` sequences, and the regular expression checks the shape of the path without validating its canonical location. The path is concatenated with `ABSPATH` and read by PHP.

The local probe confirmed that a script outside the permitted Leaflet extensions directory could be read. Impact depends on the presence of nonpublic JavaScript files accessible to the PHP process. Reading remains limited to `.js` files; reading PHP files, executing code, or modifying files was not demonstrated.

### Evidence

- [abp01-plugin-leaflet-plugins-wrapper.php](../abp01-plugin-leaflet-plugins-wrapper.php), lines 98–117, 139–150, and 164–167.
- The local input `media/js/3rdParty/leaflet-plugins/../../abp01-map.js` caused the wrapper to return the `abp01-map.js` script.

### Solution outline

1. Replace arbitrary paths with an explicit mapping between identifiers and the few supported Leaflet scripts.
2. Canonicalize paths through `realpath()` and verify that they remain within the permitted directory, including after resolving symbolic links.
3. Reject unknown inputs before reading the file. Retain extension checks as an additional measure.

**Verification after remediation:** legitimate scripts continue to work; traversal inputs, paths to other plugins, and symbolic links pointing outside the permitted directory do not return content.

## SEC-05 — Resource exhaustion through track geometry

### Finding and impact

Track simplification uses a recursive Douglas–Peucker implementation that traverses and copies lists. An upload file size limit exists, but there is no explicit limit on point count or processing cost. Public reads may trigger simplification when the cache is missing.

An account with permission to upload tracks can supply expensive geometry. Processing such tracks, particularly concurrently and without a cache, may occupy PHP workers or consume available memory. This consequence is an estimated risk; server unavailability was not induced.

### Evidence

- [Line.php](../lib/route/track/Line.php), lines 139–165: recursive algorithm.
- [Default.php](../lib/route/track/processor/Default.php), lines 213–233: on-demand simplification.
- [GetTrackDataPluginModule.php](../lib/pluginModules/GetTrackDataPluginModule.php), lines 93–95: invocation during track reads.

Local measurements on synthetic zigzag geometry, using the actual distance calculation:

| Point count | Distance calculations | Approximate time |
| --- | --- | --- |
| 250 | 8,524 | 0.015 s |
| 500 | 35,771 | 0.070 s |
| 1,000 | 185,873 | 0.294 s |

These values illustrate cost growth, not production server capacity.

### Solution outline

1. Set explicit limits on accepted point counts, segment counts, and nesting depth.
2. Precompute the simplified representation during import, in a process with controlled time and memory budgets.
3. Avoid expensive processing in public requests; use the precomputed result and return a controlled response when it is unavailable.
4. Introduce a mechanism to prevent simultaneous recalculation of the same track and define safe behavior when limits are exceeded.

**Verification after remediation:** ordinary tracks, small pathological geometries, and inputs at the accepted limit; concurrent requests with a missing cache in an isolated environment. Verify limits and recovery after processing is interrupted.

## SEC-06 — JavaScript libraries missing security fixes

### Finding and impact

The copies bundled with the plugin include:

- **Chart.js 2.9.3**, predating the prototype pollution fix associated with CVE-2020-7746; the fix was included in 2.9.4.
- **URI.js 1.19.2**, predating several security fixes concerning URL interpretation.

The presence of these versions is confirmed. It was not demonstrated that an attacker can control the parameters required for exploitation through the plugin's existing flows. The severity of a library vulnerability does not automatically apply to the entire plugin.

### Evidence and references

- [Chart.js](../media/js/3rdParty/chartjs/Chart.js), line 2.
- [URI.js](../media/js/3rdParty/uri/URI.js), line 4.
- [Chart.js fix in the official project](https://github.com/chartjs/Chart.js/pull/7920).
- [CVE-2020-7746 advisory](https://github.com/advisories/GHSA-h68q-55jf-x68w).
- [Official URI.js changelog](https://github.com/medialize/URI.js/blob/gh-pages/CHANGELOG.md).

### Solution outline

1. Inventory the libraries actually shipped in `media/js/3rdParty`, including bundle and minified files; the current npm manifests do not automatically cover them.
2. Update the copies to compatible versions containing the required fixes. For Chart.js, 2.9.4 is the threshold for the cited fix, not a general recommendation for the current version to use.
3. Update the variants used in production and the asset cache identifiers.
4. Introduce a reproducible record of versions and periodic advisory checks.

**Verification after remediation:** map and altitude profile loading, AJAX URL construction, administrative forms, and confirmation of the versions of files actually served.

## SEC-07 — Unsafe cache deserialization

### Finding and impact

Reading documents and altitude profiles from the cache uses `unserialize()` without restricting classes. A local probe confirmed execution of a synthetic class's `__wakeup()` method.

Exploitation requires an attacker to be able to modify cache files or the serialized source through another vulnerability. No such path was identified. The risk of code execution also depends on the available classes and their behavior; this is not a demonstration of RCE through the plugin's endpoints.

### Evidence

- [Document.php](../lib/route/track/Document.php), lines 76–80.
- [AltitudeProfile.php](../lib/route/track/AltitudeProfile.php), lines 55–59.
- [Default.php](../lib/route/track/processor/Default.php), lines 108–112 and 240–254: reading cache files.

### Solution outline

1. Prefer a data format without automatic class instantiation, such as JSON, with explicit reconstruction of objects after validation.
2. As an interim measure, use a restrictive `allowed_classes` list and validate the resulting type and internal structure. Classes of nested objects must be explicitly inventoried.
3. Treat invalid cache data as a cache miss without using it partially. Invalidate the old format during migration.
4. Maintain restrictive storage permissions. Blocking HTTP reads does not replace protection against unauthorized writes.

**Verification after remediation:** an object of a disallowed class does not execute its deserialization methods; corrupted files or files in the old format are rejected in a controlled manner; legitimate tracks are reconstructed correctly.

## Proposed remediation order

1. **SEC-01 and SEC-02:** close data disclosure paths and protect storage.
2. **SEC-04 and SEC-03:** restrict the files served by the wrapper and eliminate unsafe HTML concatenation.
3. **SEC-05 and SEC-06:** introduce processing limits and concurrency control, and update bundled libraries.
4. **SEC-07:** migrate the cache format or restrict deserialization, invalidating existing caches.

## Verification limitations

- No live site testing, database changes, or server load tests were performed.
- The isolated probes confirm the described behaviors but do not replace complete verification in a WordPress staging environment.
- `composer audit --locked --no-dev --format=json` could not contact Packagist from the available environment. The automated PHP dependency audit remained incomplete.
- No XXE vulnerability was confirmed in the GPX probe on PHP 8.4.0 / libxml 2.11.9: the external entity loader was not called, and the test entity was not expanded. Using SimpleXML alone is not evidence of XXE; see also the [PHP documentation](https://www.php.net/manual/en/function.libxml-disable-entity-loader.php).
- This report applies to the local copy reviewed on the stated date, not to all published versions or unverified server configurations.
