# Video production

## Choose the film from the request

The existing `brag-output/` project is a useful creative starting point: Romanian, 22 seconds, landscape, navy/mint identity, animated upload-to-map story. Read its plan, brief, credits and validation before reuse. Its recorded checks describe that historical render. Some source paths have since become unavailable, and its UI includes reconstructions and illustrative values; resolve those before presenting a new film as a current demonstration.

| Deliverable | Suggested scope | Primary CTA |
| --- | --- | --- |
| Main product presentation | 35–45 s; result, author workflow, practical detail | View the real demo or install from WordPress.org |
| Explicit `/brag` | 15–25 s; one memorable benefit and product proof | One chosen product destination |
| Developer demonstration | 45–60 s, or longer if needed to read the example | Open the tested example / developer documentation |

These are starting points, not compulsory durations. The user's format and purpose win. A strategy/storyboard request does not authorize starting a render.

## Suggested main-film story

For a 40-second first cut, use the same actual trip throughout:

| Time | Visual | Message / evidence |
| --- | --- | --- |
| 0–4 s | Author's trip photo, then the published article | A travel story readers can use |
| 4–10 s | Published summary, map and elevation profile | Show the finished result before asking the viewer to learn the workflow |
| 10–22 s | Real editor: choose trip type, enter practical details, import a track | Show which information is entered and which comes from the track; do not imply all fields are generated automatically |
| 22–32 s | Published result; one readable interaction with map/profile | Reader benefit and the relationship to the original story |
| 32–36 s | Brief supported-trip-type or customization cue | One verified secondary point |
| 36–40 s | Product name, logo and one destination | Hold the CTA long enough to read |

Adapt the order if actual footage tells the story better. Time compression is an edit, not an import-speed claim. Never infer measured distance/climb from unrelated imagery. For a developer film, substitute a real integration problem → short source excerpt → visible result → link to the complete runnable example. Do not squeeze long code into a social video.

## Route to the production skills

Read `hyperframes` first for video work. When the user explicitly requests `/brag`, use the installed `brag:brag` workflow for the creative plan and delivery, and HyperFrames' domain skills for composition, validation and rendering. Avoid a second generic intake after the brief already establishes the objective. For a longer presentation, follow the appropriate HyperFrames route. This reference supplies product context; it does not replace the current runtime contract or CLI instructions.

Use the existing project for a requested edit; create a separate campaign directory for a new film so the prior experiment remains available. Discover the current toolchain and inspect `brag-output/run-hyperframes.ps1` before assuming its local tooling still exists. Keep render dependencies isolated from plugin runtime dependencies. If specialized tools are absent, deliver the requested planning/copy and state the missing production capability.

Use approved personal travel images from [the photo brief](photo-brief.md) and current product captures from [the visual workflow](visual-assets.md). Carry the campaign evidence table and asset register into the composition brief. For a map screenshot, preserve the relevant attribution. Verify the rights and credits of music, fonts and footage rather than assuming “bundled” permits every distribution.

## Accessibility, exports and QA

Make the core meaning understandable muted. Provide readable on-screen copy; if narration is used, also deliver accurate subtitles and a transcript. Separate languages into intentional versions with consistent UI labels and captions. Recompose vertical versions instead of cropping away the product result.

Deliver the editable composition, final MP4, selected poster, captions/transcript when applicable, share copy, credits and validation notes. Keep the actual version, dimensions and duration with the export. Do not promise files before rendering finishes.

Follow the active workflow's checks and preview process. Inspect opening, transitions, settled product states and final CTA. Watch the final export for legible text, matching route data, missing assets, cut-off attribution, flash frames and audio problems; inspect its duration, video/audio streams and decoding with available media tools. Document unavailable checks. A passed composition check alone does not prove the MP4 was rendered correctly. Uploading to a video platform or sharing with an audience is a separate external action requiring authorization for that destination.
